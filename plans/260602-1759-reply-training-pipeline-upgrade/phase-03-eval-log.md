## Overview

Add a new MongoDB collection `ReplyEvalLog` that records every prompt → AI output pair, plus the metadata needed to measure the four KPIs the user listed:

1. **Style drift** — does the AI's tone/slang drift over time vs the CEO's learned profile?
2. **Blacklist violation rate** — does the AI use words the role config bans?
3. **Suggestion acceptance rate** — of AI suggestions, how many does the admin accept without editing?
4. **Edit ratio** — when admin does edit, how much of the AI text do they change? (Levenshtein distance / AI length)

The collection is **append-only** (no updates) and indexed for fast aggregation queries. A simple `/api/eval/reply-stats` endpoint exposes aggregate counts for dashboarding.

This phase does **not** compute the metrics — it logs the raw data. Aggregation queries are run by the analyst (manually, or by a future dashboarding job). KISS.

---

## Requirements

- New `ReplyEvalLog` Mongoose model with sub-documents for prompt, output, and metrics.
- Logged for every reply generated by `replyEngineService.generateSuggestions()` (KOL path) and `selfReplyService.queueSelfReplyGeneration()` (self-reply path).
- Logged **after** the AI result is received, not before (so we capture output + tokens).
- `prompt_hash` for de-duplication (SHA-256 of the prompt string, first 16 hex chars).
- `tone_used` mirrors the existing `EReplyTone` enum.
- `edit_ratio` is computed at admin-decision time (in `processExecutionResult` and `approveSuggestion`), not at log time.
- Indexed by `created_at` (time series) and `model` (per-model analysis).

  suggestion_id?: string;       // KolReplySuggestion._id for KOL path
  self_reply_queue_id?: string; // SelfReplyQueue._id for self-reply path
  parent_post_id?: string;      // KolPost._id or Post._id

  prompt_length_tokens_est: number;  // ~chars/4 heuristic
  
  // Output

  output_text: string;          // The reply text the AI generated

  // Blacklist hits (computed at log time)
  blacklisted_words_found: string[];  // Words from role config that appear in output_text
  
  // Timestamps
  created_at: Date;             // When the AI generation was queued
  decided_at?: Date;            // When admin made the decision (or null if pending)
}

const replyEvalLogSchema = new Schema<IReplyEvalLog>({
  source: { type: String, enum: Object.values(EEvalLogSource), required: true },
  suggestion_id: { type: String, index: true, sparse: true },
  self_reply_queue_id: { type: String, index: true, sparse: true },

  reply_id: { type: String, index: true, sparse: true },
  
  prompt_hash: { type: String, required: true, index: true },
  model: { type: String, required: true, index: true },
  prompt_length_chars: { type: Number, required: true },
  prompt_length_tokens_est: { type: Number, required: true },
  
  tone_used: { type: String, required: true },
  output_text: { type: String, required: true },
  output_length_chars: { type: Number, required: true },
  
  admin_decision: { type: String, enum: ["approved", "edited", "rejected", "auto_afk", "auto_manual"] },
  admin_edited_text: { type: String },
  edit_ratio: { type: Number, min: 0, max: 1 },
  
  blacklisted_words_found: { type: [String], default: [] },

// Time-series query: last 7/30 days of logs

// Per-suggestion: show all generations for a single suggestion
replyEvalLogSchema.index({ suggestion_id: 1, created_at: -1 });
// Aggregate by model

### `src/services/replyEvalService.ts` (~120 lines)

```typescript
import { createHash } from "node:crypto";
import { log } from "../utils/logger.js";
import { settings } from "../config/settings.js";
import { ReplyEvalLog, EEvalLogSource, type IReplyEvalLog } from "../db/models/ReplyEvalLog.js";

function hashPrompt(prompt: string): string {
  return createHash("sha256").update(prompt).digest("hex").slice(0, 16);
}

function findBlacklistHits(text: string, blacklist: string[]): string[] {
  if (!blacklist || blacklist.length === 0) return [];
  const lower = text.toLowerCase();
  return blacklist.filter((word) => lower.includes(word.toLowerCase()));
}

/** Compute Levenshtein-based edit ratio: 0 = identical, 1 = completely different. */
export function computeEditRatio(original: string, edited: string): number {
  if (!original) return edited ? 1 : 0;
  // Cheap heuristic: word-level Jaccard distance. Not a true Levenshtein but close enough for KPIs.
  const a = new Set(original.toLowerCase().split(/\s+/).filter(Boolean));
  const b = new Set(edited.toLowerCase().split(/\s+/).filter(Boolean));
  const intersection = new Set([...a].filter((x) => b.has(x)));
  const union = new Set([...a, ...b]);
  if (union.size === 0) return 0;
  return 1 - intersection.size / union.size;
}

export interface ILogReplyInput {
  source: EEvalLogSource;
  suggestion_id?: string;
  self_reply_queue_id?: string;
  parent_post_id?: string;
  prompt: string;
  outputText: string;
  toneUsed: string;
  model?: string;
}

export async function logReply(input: ILogReplyInput): Promise<IReplyEvalLog | null> {
  try {
    const blacklist = settings.role.blacklistedWords ?? [];
    return await ReplyEvalLog.create({
      source: input.source,
      suggestion_id: input.suggestion_id,
      self_reply_queue_id: input.self_reply_queue_id,
      parent_post_id: input.parent_post_id,
      prompt_hash: hashPrompt(input.prompt),
      model: input.model ?? settings.openClawReplyModel,
      prompt_length_chars: input.prompt.length,
      prompt_length_tokens_est: Math.ceil(input.prompt.length / 4),
      tone_used: input.toneUsed,
      output_text: input.outputText,
      output_length_chars: input.outputText.length,
      blacklisted_words_found: findBlacklistHits(input.outputText, blacklist),
    });
  } catch (err: unknown) {
    log.error(`[ReplyEval] Failed to log reply: ${(err as Error).message}`);
    return null;
  }
}

export interface IRecordDecisionInput {
  reply_eval_log_id?: string;  // Direct link
  suggestion_id?: string;
  self_reply_queue_id?: string;
  output_text: string;          // AI output (for edit_ratio calc)
  decision: "approved" | "edited" | "rejected" | "auto_afk" | "auto_manual";
  edited_text?: string;
}

export async function recordDecision(input: IRecordDecisionInput): Promise<void> {
  const filter = input.reply_eval_log_id
    ? { _id: input.reply_eval_log_id }
    : input.suggestion_id
      ? { suggestion_id: input.suggestion_id }
      : { self_reply_queue_id: input.self_reply_queue_id };
  if (!filter) return;
  const update: Record<string, unknown> = {
    admin_decision: input.decision,
    decided_at: new Date(),
  };
  if (input.edited_text) {
    update.admin_edited_text = input.edited_text;
    update.edit_ratio = computeEditRatio(input.output_text, input.edited_text);
  } else if (input.decision === "approved" || input.decision === "auto_afk") {
    update.edit_ratio = 0;
  } else if (input.decision === "rejected") {
    update.edit_ratio = 1;
  }
  await ReplyEvalLog.updateOne(filter, { $set: update });
}
```

### `src/routes/replyEval.ts` (~50 lines)

Read-only aggregate endpoints. No PII, no secrets. Used by the human operator to check the four KPIs.

```typescript
import { Router, type Request, type Response } from "express";
import { ReplyEvalLog } from "../db/models/ReplyEvalLog.js";

export const replyEvalRouter = Router();

replyEvalRouter.get("/stats", async (req: Request, res: Response) => {
  try {
    const days = Math.max(1, Math.min(90, parseInt((req.query.days as string) ?? "7", 10)));
    const since = new Date(Date.now() - days * 86_400_000);
    const logs = await ReplyEvalLog.find({ created_at: { $gte: since } }).lean();
    
    if (logs.length === 0) {
      return res.json({ days, total: 0 });
    }
    
    const total = logs.length;
    const decided = logs.filter((l) => l.admin_decision);
    const edited = decided.filter((l) => l.admin_decision === "edited");
    const approved = decided.filter((l) => l.admin_decision === "approved" || l.admin_decision === "auto_afk");
    const rejected = decided.filter((l) => l.admin_decision === "rejected");
    const withBlacklistHits = logs.filter((l) => l.blacklisted_words_found.length > 0);
    const avgEditRatio = edited.length > 0
      ? edited.reduce((s, l) => s + (l.edit_ratio ?? 0), 0) / edited.length
      : null;
    
    res.json({
      days,
      total,
      decided: decided.length,
      approved_count: approved.length,
      edited_count: edited.length,
      rejected_count: rejected.length,
      approval_rate: decided.length > 0 ? approved.length / decided.length : null,
      edit_rate: decided.length > 0 ? edited.length / decided.length : null,
      avg_edit_ratio: avgEditRatio,
      blacklist_violation_rate: total > 0 ? withBlacklistHits.length / total : null,
    });
  } catch (e: unknown) {
    res.status(500).json({ success: false, error: (e as Error).message });
  }
});

replyEvalRouter.get("/recent", async (req: Request, res: Response) => {
  try {
    const limit = Math.min(100, parseInt((req.query.limit as string) ?? "20", 10));
    const logs = await ReplyEvalLog.find().sort({ created_at: -1 }).limit(limit);
    res.json({ success: true, logs });
  } catch (e: unknown) {
    res.status(500).json({ success: false, error: (e as Error).message });
  }
});
```

## Risk Assessment

| Risk | Likelihood | Mitigation |
|------|------------|------------|
| `ReplyEvalLog` collection grows unboundedly | High (eventual) | Add TTL index in Phase 3.1 follow-up: `replyEvalLogSchema.index({ created_at: 1 }, { expireAfterSeconds: 90 * 86400 })` (90-day retention). Not in this phase — measure first, then prune. |
| Logged `output_text` may contain PII (user mentions, quoted tweets) | Medium | This is **internal eval data**, not exposed publicly. The `/api/eval/recent` endpoint should require auth (verify in `app.ts` — does the API have a global auth middleware? If yes, the eval router inherits it. If no, leave it open and add a TODO). |
| Computing `edit_ratio` via Jaccard is not a true Levenshtein | Low | Acceptable for KPIs. A real Levenshtein is O(n×m) and would slow webhook responses. The user's stated need is "edit_ratio (user edits vs AI output)" — Jaccard distance over word sets captures the same intent at a fraction of the cost. |
| Re-building the prompt in `processGeneratedSuggestions` may diverge from the original due to non-deterministic `OwnAccountProfile` reads | Low | Profile is read fresh on each call (no caching). The build is deterministic for a given profile snapshot. Worst case: the logged `prompt_hash` doesn't match the actually-used prompt. Logged hash is for aggregation, not replay. |
| Phase 03 produces data that reveals Phase 02's injection isn't helping | Intended | This is the **point** of the eval log. If `edit_ratio` doesn't improve, the team should consider raising `MIN_POSTS_REQUIRED` (Phase 1) or re-evaluating the learned profile gate (`learning_confidence >= 60`). Phase 03 is the early-warning system. |

## Security Considerations

- `ReplyEvalLog` is **internal** — no public API. The `/api/eval/*` endpoints should sit behind the same auth middleware as the rest of the API (verify in `app.ts`).
- The eval log contains AI-generated text, which is not sensitive. But it also contains admin edits, which may include private reasoning. Treat as confidential.
- `blacklisted_words_found` is computed against the role config's blacklist. If the blacklist is updated, historical logs are not re-scanned (intentional — historical view is immutable).
